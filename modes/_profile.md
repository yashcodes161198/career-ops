# Internship candidate profile context

## Target roles

| Archetype | What to look for |
|---|---|
| Software Developer Intern | Programming, data structures, tested projects; treat as equivalent to Software Engineering Intern |
| Software Engineering Intern | Programming fundamentals, data structures, tested projects |
| Backend Engineering Intern | APIs, databases, server-side code, debugging, Docker |
| Machine Learning / AI Intern | Model fine-tuning, inference services, agents, Python ML tooling |
| Data Science / Data Engineering Intern | SQL, analytics pipelines, data stores, applied stats or ETL |
| Platform or Distributed Systems Intern | Linux, containers, clusters, networking, monitoring |

Do not target civil engineering roles. Frontend-only and mobile-only roles are secondary.

## Evaluation policy

- Score against internship expectations, not senior-engineer expectations.
- Treat enrollment status and graduation window (July 2027) as eligibility signals.
- Treat required prior full-time experience as a likely blocker.
- Do not penalize the candidate for lacking staff-level leadership or system ownership.
- Separate required qualifications from preferred qualifications.
- Prefer roles whose required skills have evidence in `cv.md`.
- Treat **Software Developer Intern**, **Software Development Intern**, and **Developer Intern** as primary targets equivalent to Software Engineering Intern.
- Accept coursework, projects, research, open source, and previous internships as evidence when each claim is explicit in the candidate's files.
- Never infer a technology, metric, user count, or impact from a project title.
