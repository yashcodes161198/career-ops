# Internship candidate profile context

This file contains reusable internship-level scoring rules. Replace bracketed
placeholders after adding the candidate's CV and `config/profile.yml`.

## Target roles

| Archetype | What to look for |
|---|---|
| Software Engineering Intern | Programming fundamentals, data structures, tested projects |
| Backend Engineering Intern | APIs, databases, server-side code, debugging |
| Platform or Cloud Engineering Intern | Linux, containers, CI/CD, cloud coursework or projects |

Remove archetypes the candidate is not targeting. Add frontend, mobile, data,
security, or machine-learning internships only when the CV supports that
direction.

## Evaluation policy

- Score against internship expectations, not senior-engineer expectations.
- Treat enrollment status and graduation window as eligibility signals.
- Treat required prior full-time experience as a likely blocker.
- Do not penalize the candidate for lacking staff-level leadership or system
  ownership.
- Separate required qualifications from preferred qualifications.
- Prefer roles whose required skills have evidence in `cv.md`.
- Accept coursework, projects, research, open source, and previous internships
  as evidence when each claim is explicit in the candidate's files.
- Never infer a technology, metric, user count, or impact from a project title.

## Candidate narrative

Build the narrative only from `cv.md`, `config/profile.yml`, and facts the
candidate confirms directly. Do not copy another candidate's positioning.

## Location and work authorization

- Read the candidate's actual location and authorization from
  `config/profile.yml`.
- Flag country, residency, enrollment, and sponsorship restrictions.
- Do not interpret "remote" as "remote worldwide."
- Never infer willingness to relocate.

## Availability

Read internship start date, end date, duration, and semester constraints from
the candidate's confirmed profile. If any are missing and the posting requires
them, ask before recommending an application.

## Proof policy

- Use only candidate-confirmed facts.
- Never invent grades, project users, performance gains, team size, business
  impact, availability, or work authorization.
- Keywords may be reformulated but skills may not be fabricated.
- A missing preferred framework can be bridgeable. A hard eligibility mismatch
  usually is not.

## Compensation

Use only the candidate's stated stipend needs. If no minimum exists, record
compensation as open rather than guessing.
