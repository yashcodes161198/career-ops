# Fresher candidate profile context

This file contains reusable fresher-level scoring rules. Replace bracketed
placeholders after adding the candidate's CV and `config/profile.yml`.

## Target roles

| Archetype | What to look for |
|---|---|
| Associate / Junior Software Engineer | Programming fundamentals, projects, coursework, 0-2 years experience |
| Graduate Engineer Trainee (GET) | Structured training programs, campus or off-campus hiring |
| Backend Engineer (Fresher) | APIs, databases, server-side projects, debugging |
| Full Stack Engineer (Fresher) | Web apps, frontend + backend project evidence |
| Data / ML Engineer (Fresher) | Coursework, Kaggle, projects, research — only if CV supports it |

Remove archetypes the candidate is not targeting. Add frontend, mobile, DevOps,
or security only when the CV supports that direction.

## Evaluation policy

- Score against fresher and 0-2 year expectations, not senior-engineer expectations.
- Treat graduation window and campus eligibility as hard signals.
- Treat "3+ years required" or "5+ years required" as likely blockers.
- Do not penalize the candidate for lacking staff-level leadership or system ownership.
- Separate required qualifications from preferred qualifications.
- Prefer roles whose required skills have evidence in `cv.md`.
- Accept coursework, projects, internships, research, open source, and hackathons
  as evidence when each claim is explicit in the candidate's files.
- Never infer a technology, metric, user count, or impact from a project title.

## Candidate narrative

Build the narrative only from `cv.md`, `config/profile.yml`, and facts the
candidate confirms directly. Do not copy another candidate's positioning.

## Location and work authorization

- Read the candidate's actual location and authorization from `config/profile.yml`.
- Flag country, residency, and sponsorship restrictions.
- Do not interpret "remote" as "remote worldwide."
- Never infer willingness to relocate.

## Availability

Read earliest join date, notice period, and relocation constraints from the
candidate's confirmed profile. If any are missing and the posting requires them,
ask before recommending an application.

## Proof policy

- Use only candidate-confirmed facts.
- Never invent grades, project users, performance gains, team size, business
  impact, availability, or work authorization.
- Keywords may be reformulated but skills may not be fabricated.
- A missing preferred framework can be bridgeable. A hard eligibility mismatch
  usually is not.

## Compensation

Use only the candidate's stated salary needs. If no minimum exists, record
compensation as open rather than guessing.
